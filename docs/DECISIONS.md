# CookCoach 결정 로그

확정된 결정을 날짜순으로 추가한다. 기존 결정을 몰래 덮어쓰지 않고 상태가 바뀌면 새 항목으로 기록한다.

## 대표 시연 메뉴

날짜: 2026-08-10

결정: 규동을 공모전 영상과 실제 앱 시연의 기준 메뉴로 사용한다.

이유: CookCoach의 SCAN → PLAN → COACH → REVIEW 전체 흐름을 일관되게 보여주기 위한 Golden Path가 필요하다.

상태: 확정

## SCAN 순서와 데모 진입

날짜: 2026-08-10

결정: SCAN을 냉장고 → 영수증의 고정 순서로 진행하고, 각 단계를 독립적으로 건너뛸 수 있게 한다. 둘 다 건너뛰면 규동용 데모 냉장고 선택 안내를 표시한다.

이유: 냉장고와 영수증을 함께 활용하면서도 카메라 없이 공모전 Golden Path를 안정적으로 시연하기 위해서다.

상태: 확정

## 필수 재료와 요리 시작 제한

날짜: 2026-08-10

결정: 레시피의 필수 재료가 없으면 메뉴 상세에서 부족 수량을 안내하고 COACH 시작 버튼을 비활성화한다. 사용자가 재료를 추가하거나 `준비했어요`로 반영하면 다시 시작할 수 있다.

이유: 핵심 재료 없이 조리를 시작하는 잘못된 사용자 흐름을 막기 위해서다.

상태: 확정

## Phase 2 최소 영구 저장

날짜: 2026-08-10

결정: 재료 목록과 식사 완료 기록을 localStorage에 저장한다. 식사 기록은 날짜별 배열로 관리해 같은 날 여러 메뉴를 보존한다.

이유: 새로고침 후 기록 손실을 막고 캘린더에서 실제 메뉴 이력을 보여주기 위해서다.

상태: 확정

## 규동 이미지 fallback

이유: broken image 노출과 레이아웃 흔들림을 막으면서 향후 이미지 파일만 교체할 수 있게 하기 위해서다.

상태: 확정

이유: 기존 정상 기능을 보호하고 공모전 시연 안정성과 Netlify 정적 배포 가능성을 우선하기 위해서다.

이유: 원본 비교와 회귀 확인을 가능하게 하면서 정적 배포 진입점을 준비하기 위해서다.

이유: 사용자 주도 시작과 공모전 시연 타이밍의 안정성을 보장하기 위해서다.

이유: 확정되지 않은 레시피나 임시 이미지를 제품 사실처럼 노출하지 않기 위해서다.

이유: 현재 조리 상황과 무관한 FAQ 노출을 없애고 AI 기능 범위를 과장하지 않기 위해서다.

이유: 실제 사용자 기록을 보존하면서 공모전 첫 시연에서도 캘린더의 날짜별·복수 메뉴 기능을 보여주기 위해서다.

이유: 백엔드 없이도 새로고침 후 사용자 설정을 유지하고 여러 저장 체계가 늘어나는 것을 막기 위해서다.

상태: 확정

## 카메라 오류 진단과 복구

날짜: 2026-08-10

결정: 카메라 미리보기와 촬영을 분리하고, 오류 종류를 콘솔과 사용자 안내에서 구분한다. 촬영 종료 시 모든 track과 `video.srcObject`를 해제하며 실패 시 재시도·사진 선택·건너뛰기를 제공한다.

이유: 카메라 실패 원인을 숨기지 않으면서도 SCAN과 규동 Golden Path를 계속 진행할 수 있게 하기 위해서다.

상태: 확정

## 데스크톱 카메라 fallback과 오류 Bottom Sheet

날짜: 2026-08-10

결정: 냉장고와 영수증은 동일한 camera controller에서 후면 카메라를 우선 요청하고, 장치 선택·제약 오류 시 `video: true` 기본 카메라를 한 번 더 요청한다. 두 요청이 실패하면 중앙 팝업 대신 접을 수 있는 bottom sheet에서 다시 시도·사진 선택·건너뛰기를 제공한다.

이유: 모바일에서는 후면 카메라를 우선하면서도 Mac처럼 후면 카메라 개념이 없는 환경에서 내장 웹캠으로 개발 테스트할 수 있게 하고, 오류 복구 동작을 모바일 화면 아래에 일관되게 배치하기 위해서다.

상태: 확정

## 전역 Bottom Sheet Controller와 환경별 카메라 요청

날짜: 2026-08-10

결정: 회색 handle이 있는 모든 하단 sheet는 `bottom-sheet.js`의 공통 controller로 열기·닫기·drag·backdrop·스크롤 충돌을 처리한다. 앞선 후면 우선 카메라 결정은 모바일에만 적용하고, 데스크톱은 `{ video: true }` 기본 카메라를 첫 요청으로 사용한다. 요청 전과 실패 후 `enumerateDevices`를 포함한 환경 진단을 console에 기록한다.

이유: sheet마다 복제된 gesture 코드를 없애고 건강목표 같은 긴 sheet의 스크롤을 보존하며, 후면 카메라 개념이 없는 Mac에서 불필요한 environment 요청 없이 내장 또는 Continuity Camera를 시작하기 위해서다.

상태: 확정 — 이 결정이 `데스크톱 카메라 fallback과 오류 Bottom Sheet`의 데스크톱 요청 순서를 대체한다.

## 스트릭과 식사 완료 저장

날짜: 2026-08-10

결정: 스트릭은 중복 제거한 식사 날짜를 오늘 또는 가장 최근 기록부터 역순으로 계산한다. REVIEW 저장은 요리 완료 token당 한 번만 허용하고 저장 직후 마이페이지와 오늘 메뉴를 갱신한다.

이유: 하루 복수 식사를 스트릭 일수로 중복 계산하지 않고, 빠른 재탭으로 식사·재고가 중복 반영되는 것을 막기 위해서다.

상태: 확정

이유: 선택한 목표와 마이페이지 리포트가 일치하도록 하면서 의료적 진단이나 효능을 과장하지 않기 위해서다.

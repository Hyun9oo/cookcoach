# CookCoach 사용자 흐름

## 핵심 앱 흐름

```text
SCAN → TABLE → COACH → REVIEW → 마이페이지
```

- SCAN: 냉장고·영수증 촬영과 재료 확인
- TABLE: 상황·콘셉트 선택, 메뉴 추천·선택, 메뉴 상세 확인
- COACH: 단계별 조리 안내, 타이머, `도와주세요!`와 실수 대응
- REVIEW: 요리 완료 결과와 사용 재료 확인, `오늘의 한 끼 기록하기`
- 마이페이지: 저장된 식사 기록, 캘린더, 스트릭, 건강 목표와 프로필 확인

`TABLE`은 현재 상황 선택·메뉴 추천·메뉴 상세 흐름을 묶어 부르는 단계이며, 별도 화면을 뜻하지 않는다.

## 전체 흐름


## 시작

- 첫 화면은 시간이 지나도 자동으로 넘어가지 않는다.
- 사용자가 `CookCoach 시작하기`를 눌렀을 때만 앱을 시작한다.

## 촬영 분기

다음 네 가지 경우를 모두 지원해야 한다.

- 냉장고만 촬영
- 영수증만 촬영
- 냉장고와 영수증 모두 촬영
- 냉장고와 영수증 모두 건너뛰기

둘 다 건너뛰면 규동 Golden Path를 진행할 수 있는 데모 냉장고를 사용한다.

촬영 완료 상태에서는 바로 재료 확인으로 이동하지 않는다.

- 냉장고 촬영 완료 → `다음 · 영수증`
- 냉장고 건너뛰기 → 영수증 단계
- 영수증 촬영 완료 → `재료 확인`
- 영수증 건너뛰기 → 촬영된 정보가 있으면 재료 확인
- 둘 다 건너뛰기 → 데모 냉장고 안내

카메라 요청이 실패하면 오류 원인을 안내하고 다음 대안을 제공한다.

- 다시 시도
- 사진 선택
- 현재 촬영 단계 건너뛰기

카메라 장치 요청은 실행 환경에 따라 나눈다. Mac 등 데스크톱은 별도 facingMode 없이 기본 카메라를 먼저 요청한다. 터치 기반 모바일 환경은 후면 카메라를 우선 요청하고, 장치 선택 또는 제약 문제로 실패하면 기본 카메라를 다시 요청한다. 최종 요청이 실패하면 `enumerateDevices` 결과와 오류 종류를 함께 확인하고 화면 아래의 안내 sheet에서 다시 시도·사진 선택·건너뛰기를 제공한다. 권한 거부·보안 환경·API 미지원 오류는 동일 요청을 반복하지 않고 원인을 바로 안내한다.

회색 handle이 있는 모든 하단 sheet는 같은 interaction을 사용한다. handle 클릭, backdrop 클릭, 충분한 아래 방향 drag로 닫을 수 있고 기준 미만 drag는 원래 위치로 돌아간다. 긴 콘텐츠는 내부 스크롤이 우선하며 상단에 도달한 상태에서 아래로 drag할 때만 sheet dismiss가 시작된다.

카메라는 첫 사용자 동작에서 미리보기를 연 뒤 별도의 `촬영` 동작으로 사진을 확정한다. 냉장고 촬영이 끝나면 MediaStream의 모든 track과 video 연결을 해제하고, 영수증 단계에서 새 stream을 요청한다.

## COACH 도움 흐름

`도와주세요!`는 현재 레시피와 현재 STEP의 대표 문제·해결 방법을 먼저 표시한다. `다른 문제가 있나요?`에서는 범용 FAQ를 노출하지 않고 사용자가 상황을 직접 입력한다. 자유 질문에는 새로운 요리 지식이나 공식 해결 방법을 답변처럼 생성하지 않고, 향후 단계별 도움말 개선에 참고한다는 공통 안내만 표시한다.

9개 메뉴의 56개 모든 STEP에는 대표 질문과 답변이 하나씩 연결된다. 기존 둘이서 3개 메뉴의 18개 도움말은 문구와 STEP mapping을 그대로 유지한다.

## REVIEW와 마이페이지

- REVIEW에서 저장한 실제 식사 기록은 오늘 날짜에 추가한다.
- `오늘의 한 끼 기록하기`를 여러 번 눌러도 같은 요리 완료 token은 한 번만 저장하고, 저장 직후 마이페이지를 활성화한다.
- 오늘 날짜 캘린더에는 저장한 실제 메뉴명을 표시한다.
- 식사 기록이 완전히 비어 있고 데모 기록을 생성한 적이 없을 때만 최근 6일 상대 날짜에 데모 식사 기록을 한 번 생성한다.
- 스트릭은 날짜별 식사 수와 무관하게 하루를 1일로 세고, 오늘 기록이 있으면 오늘부터, 없으면 가장 최근 기록부터 연속 날짜를 계산한다. 월 경계는 끊김으로 취급하지 않는다.
- 마이페이지에서 이름, 압축된 프로필 사진, 기본 및 직접 입력 건강 목표를 수정하고 브라우저에 저장한다.
- 기본 건강 목표는 목표별로 서로 다른 요약과 확인 기준을 표시하고, 직접 목표는 의료적 판단이 아닌 일반적인 기록 안내를 표시한다.

## 현재 구현 상태

Phase 2에서 냉장고 → 영수증 순차 흐름과 네 가지 촬영/건너뛰기 조합을 구현했다. Phase 3에서 카메라 미리보기와 촬영 동작을 분리하고, 오류별 안내·재시도·사진 선택 fallback을 추가했다. Phase 4에서 모든 handle 기반 sheet를 공통 dismiss UX로 통합하고, 데스크톱 기본 카메라 우선·모바일 후면 선호 fallback과 장치 진단을 적용했다. GitHub Pages 모바일 보완에서 100dvh·safe area, 9개 메뉴 원문 도움말, 건강 목표별 기준, 실제 기록 기반 스트릭과 REVIEW 저장 후 마이페이지 이동을 적용했다. 현재 Golden Path는 `START → SCAN → TABLE(상황 선택·메뉴 추천·상세) → COACH → REVIEW → 오늘의 한 끼 기록 → 마이페이지`로 연결된다. 두 촬영 결과는 하나의 재료 확인 목록으로 합쳐진다. 둘 다 건너뛰면 규동 핵심 재료가 있는 데모 냉장고 안내를 표시한다.

실제 영수증 OCR은 아직 구현하지 않으며 현재 영수증 촬영 결과는 데모 인식 데이터다.
